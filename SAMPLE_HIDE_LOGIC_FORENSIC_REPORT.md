# SAMPLE AUTO-HIDE LOGIC FORENSIC REPORT

## Scope

Read-only investigation. No source code was modified.

Target behavior:

1. A matching LIVE property hides the matching SAMPLE property.
2. Removing or archiving the LIVE property makes the SAMPLE property visible again.

## Finding Summary

| Sample property definition exists | PASS |

| Case 1: matching LIVE property hides SAMPLE property | **FAIL** |

## Complete Path Trace

### 1. `searchInventory()`

File: [src/data/inventoryManager.ts](src/data/inventoryManager.ts#L97-L104)

```ts
export const searchInventory = async (filters: SamplePropertySearchFilters): Promise<LiveProperty[]> => {
  if (!isSupabaseConfigured) return [];

  const records = await propertyRepository.findAll();
  return records
    .map((record) => toLiveProperty(record as unknown as Record<string, any>))
    .filter((property) => matchesFilters(property, filters));
};
```

Exact break:

- With no Supabase configuration, line 98 returns `[]` immediately.
- With Supabase configuration, lines 100-103 query only `propertyRepository.findAll()` and filter those database records.
- No `SAMPLE_PROPERTIES` are returned by this function.
- No `getHiddenSampleIds()` call exists in this function.

This is the primary broken function for the requested sample hide/reveal behavior.

## CASE 1 - Matching LIVE Property Created

Input:

- Existing sample: Lahore / DHA / Phase 1 / Plot / 1 Kanal.
- Create matching live property through the List Property modal or dashboard.

Expected:

- Matching sample is hidden.
- Matching LIVE property is shown.

Actual source behavior:

### Without Supabase configuration

1. The modal stores the live property in `MEMORY_STORE` through `saveLiveProperty`.
2. The inventory update event fires.
3. `PropertyDiscoverySection` calls `searchProperties` again.
4. `searchInventory` returns `[]` at [src/data/inventoryManager.ts](src/data/inventoryManager.ts#L98).
5. No sample and no live property is shown.

Result: **FAIL**.

### With Supabase configuration

1. The modal still stores the live property in `MEMORY_STORE`, not Supabase.
2. Discovery calls `propertyRepository.findAll()`.
3. The newly created modal property is absent unless separately inserted into Supabase.
4. No sample fallback is returned.

Result: **FAIL** for the modal-to-search path.

Exact broken files/functions:

- [src/data/inventoryManager.ts](src/data/inventoryManager.ts#L97-L104), `searchInventory`
- [src/App.tsx](src/App.tsx#L455), List Property modal write path
- [src/data/inventoryManager.ts](src/data/inventoryManager.ts#L106-L111), `saveLiveProperty`
- [src/components/PropertyDiscoverySection.tsx](src/components/PropertyDiscoverySection.tsx#L39-L53), active result path

## CASE 2 - LIVE Property Archived or Removed

Input:

- Start with a matching live property in the in-memory inventory.
- Archive it or remove it.

Expected:

- Matching sample becomes visible again.

Actual source behavior:

1. `deleteLiveProperty` removes the live record from `MEMORY_STORE` at [src/data/inventoryManager.ts](src/data/inventoryManager.ts#L113-L116).
2. `archiveLiveProperty` removes the live record from the live list and places it in the archived list at [src/data/inventoryManager.ts](src/data/inventoryManager.ts#L118-L124).
3. `getHiddenSampleIds` would recalculate and no longer include the sample ID.
4. However, active `searchInventory` never calls `getHiddenSampleIds` and never returns `SAMPLE_PROPERTIES`.
5. Property Discovery therefore continues to return `[]` without Supabase, or only database rows with Supabase.

Result: **FAIL**.

Exact broken file/function:

- [src/data/inventoryManager.ts](src/data/inventoryManager.ts#L97-L104), `searchInventory`

Affected feature: sample visibility restoration after live deletion or archive.

## Root Cause

The sample hide helper and live inventory write helpers are local-memory based, but the active search path was changed to a Supabase-only result path:

- Write path: `saveLiveProperty` -> `MEMORY_STORE`.
- Active read path: `searchInventory` -> `propertyRepository.findAll()` or immediate `[]`.
- Sample path: `SAMPLE_PROPERTIES` is not included by `searchInventory`.
- Hide path: `getHiddenSampleIds` is not called by `searchInventory`.

The failure is a source-of-truth and control-flow mismatch, not a missing comparison condition in `sameInventoryKey`.

**CASE 1: FAIL**

**CASE 2: FAIL**

**Sample Auto-Hide Logic: FAIL**

1. Choose one authoritative inventory source for both live writes and discovery reads.
2. Make property creation from the List Property modal and dashboard persist through the same repository used by `searchInventory` when Supabase is configured.
3. Define the intended no-Supabase behavior explicitly; do not silently return an empty result if sample inventory is still expected in local mode.
4. Update the active search path to combine live records and sample records, excluding sample IDs returned by `getHiddenSampleIds`.
5. Ensure `deleteLiveProperty` and `archiveLiveProperty` trigger a search refresh against that same source.
6. Add a focused regression test for the exact Lahore/DHA/Phase 1/Plot/1 Kanal case:
   - sample visible before live creation;
   - sample hidden and live record visible after matching creation;
   - sample visible again after live deletion;
   - sample visible again after live archive.
7. Apply the same behavior to AI property search so it uses the same filtered result set.

# Final Business Rules Audit

> Historical source audit snapshot from before Phase 0 architecture reconciliation. Its quoted 24/72-hour and 3/15/30-day variants are now `LEGACY / NON-CANONICAL`; consult [NEXUS_CANONICAL_BUSINESS_RULES_v1.0.md](./NEXUS_CANONICAL_BUSINESS_RULES_v1.0.md) and [NEXUS_DECISION_REGISTER_v1.0.md](./NEXUS_DECISION_REGISTER_v1.0.md) for current policy and unresolved decisions. This notice preserves the historical findings below without presenting them as active policy.

## Scope and status key

Read-only audit of the checked-out source, architecture specifications, PHASE reports, and other root Markdown reports. Rules repeated in multiple files are consolidated but their source files remain listed. Product promises, intended workflows, and historical report assertions are not treated as active enforcement unless current runtime code actually enforces them.

- **Active in code** — current executable source implements the stated behavior. This does not imply that a live production backend was verified.
- **Documentation only** — stated in architecture, UI copy, or reports, but no corresponding current enforcement was found.
- **Conflicting** — current sources make inconsistent claims, or the described rule contradicts current runtime behavior.
- **Missing** — no definite rule/value/authority was found for the named subject, or the required implementation is absent.

The report files record observations from different dates and sometimes disagree. Current source code is used to describe present behavior; reports are cited as historical claims/evidence, not presumed current truth. No estimates are made.
